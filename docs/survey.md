## 2. 컨테이너

### 2.1 CPK (확인)
- `tools/cpk.py`: @UTF 표, TOC/ITOC, CRILAYLA 해제, 재구성.
- DAT000 머리말 합계: `EnabledDataSize = ΣFileSize + ΣExtractSize`, `EnabledPackedSize = 2·ΣExtractSize`, `ContentSize = align2048(파일크기 − ContentOffset)`. 파일은 2048 정렬, 사이 패딩은 0, TOC 순서 ≠ 물리 순서.
- 재구성: 물리 순서·정렬 유지, 교체 파일은 무압축 저장, TOC/머리말 고정폭 칸만 제자리 수정. **무변경 재구성 = 원본과 바이트 동일**(테스트). 교체·확장한 DAT000으로 부팅·폰트 로드 확인(PoC-F2).

### 2.2 이미지 `.pix` (확인)
- `FPIX` > `DPIX` > `XPIX` 안에 표준 PSP GIM(`MIG.00.1PSP`). RGBA8888·인덱스4/8, swizzle 사용. 디코더는 아직 scratch(도구화 예정).

### 2.3 ISO 재구성 (미해결)
- 디렉터리 부팅으로 PoC 진행 중. 배포용 ISO 재작성 경계(DAT000 크기 증가 처리)와 무변경 왕복은 아직 미확립.

## 3. 텍스트

### 3.1 대사 스크립트 `FLASH/*.srt` (구조 확인, 의미 일부 가설)
- 613 파일. `FSRT`(u32 파일크기) → +0x14 `XSRT`(u32 크기, u32 명령 수) → +0x24부터 명령 연속.
- 명령: `u32 size, u32 op, u32 argc, u32 args[argc], [인라인 문자열 SJIS + NUL, 4바이트 패딩]`. 613개 전부 끝·명령 수가 머리말과 정확히 일치.
- 문자열 명령(argc 뒤 문자열): op 0,1,2,0x1d,0x1e,0x1f,0x21,0x3a,0x3b,0x3c,0x6e (argc 2), op 3–7 (argc 4). op 3이 대표 대화(인자 4개: 4, 음성/얼굴?, 화자?, ?).
- **분기 오프셋**: `0x10002`/`0x10003`/`0x10004` arg1, `0x1000b` arg1, `0x10008` arg0 = 명령열 시작(0x24) 기준 바이트 오프셋(전 표본 일치). 의미: 10009 switch, 10002/10003 case, 1000b default, 10008 goto. 문자열 길이 변경 시 이 다섯 칸만 재배치하면 된다는 것이 현재 가설 — 런타임 분기 검증 필요.
- 문법: `@n` 줄바꿈(44,997회), `@n<…>` 127회, `⊿`(SJIS 0x8799) / `⊥` 페이지·대기 표시, 루비 `中央（セントラル）` 형태 본문 포함.
- 툴팁/튜토리얼(EBOOT)에는 `@c<NN>` 색, `@s<NNN>` 속도(가설)도 있음.

### 3.2 EBOOT 문자열 (저장 확인, 참조 구조 미해결)
- 복호화 ELF 안 SJIS NUL 종료 문자열: 스킬명, 메뉴, 튜토리얼, 시스템 대화(예: `0x16a19c` 세이브 없음 대화). 엄격 필터 1,665개 / 34,510자(디버그 문자열 포함, 상한).
- PRX라 문자열 주소는 재배치 대상. 참조 방식(lui/addiu 쌍, 포인터 표)과 여유 공간은 미조사.

### 3.3 기타
- `STR/mes_j.bin`(16,832 B): 머리말 오프셋 13개 + SJIS 이름·UI 문자열 표. `mes_e/f/g/i/s.bin` 존재(UTF-8 등). 어느 쪽을 읽는지 미해결(EBOOT에 파일명 문자열 없음).
- `.cms`: 데모 오브젝트 내부명(표시 여부 미해결, 표시 안 되는 것으로 추정). `.sop`·`.fls`: 일본어 텍스트 사실상 없음.
- 동영상 PSMF 19개: 자막·글자 포함 여부 미조사.
- 그래픽 글자: `.pix` 1,579개(해제 시 679 MB) 중 메뉴·타이틀 등 글자 그림 다수 예상, 목록 미작성.

## 4. 글꼴과 렌더링

### 4.1 FFON 형식 (확인, `tools/ffon.py`)
- 머리말 0xA0, 블록 1 = ASCII(0x20–0x7E), 선택적 반각 가나 블록, 이어 JIS 구(ku)별 블록. 블록 = u16×96(1부터 시작하는 글리프 번호, 0 = 없음). 그 뒤 글리프 비트맵.
- FAfont14: 14×16 4bpp, 글리프 2,144(ASCII·기호·PSP 버튼·가나·한자 약 1,900, 게임 전용 부분집합). cmexFontDefault: 20×20 2bpp, 3,918(JIS 1수준 전체 + 반각 가나).
- +0x04 u32 의미 미상(파일 크기 아님) — 보존 중. 글리프 수 증가 시 영향 미확인.
- 두 실제 파일 모두 parse→build 바이트 동일.

### 4.2 소비자 (일부 확인)
- **세이브 없음 대화(EBOOT 문자열)는 DAT000 안 `FAfont14.fon`으로 그린다** — PoC-F2: 네 사본에 서로 다른 무늬를 넣었고 CPK FAfont14의 무늬만 화면에 나옴. 디스크의 낱개 `.fon`은 이 경로에서 무관.
- 대사창·메뉴·전투 UI가 같은 글꼴인지는 미확인. `ID/cmn_font.pix`는 영숫자 스프라이트 글꼴(한글화 불필요 추정). `STR/libfont.prx`(시스템 글꼴 라이브러리) 사용 경로 미확인.
- 문자 → 글리프: SJIS → JIS(ku,ten) → 블록 표. 한자 자리에 한글 음절을 배정하는 방식이 형식상 가능(JIS 구 16–47에 3,008칸).
