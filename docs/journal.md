# 작업 일지

시간순 기록. 현재 결론은 `docs/survey.md`가 기준이다.

## 2026-10-26

### 환경
- PPSSPP v1.20.4 (flatpak `org.ppsspp.PPSSPP`, --user), 설정 `RemoteDebuggerOnStartup = True`.
- 디렉터리 부팅: 압축 푼 트리의 **루트**(PSP_GAME의 부모)를 인자로 줘야 함. `PSP_GAME/SYSDIR/EBOOT.BIN`을 주면 "ISO looks bogus"로 실패.
- 화면 캡처: 디버거 `gpu.buffer.screenshot`은 "Could not download output"로 실패 → X11 창 캡처(`import -window`)로 대체 (`tools/ppdbg.py`).
- 디버거 WebSocket 핸드셰이크가 디렉터리 부팅 실행에서 응답 없음(원인 미조사, 캡처에는 불필요).
- pspdecrypt `c156627` (work/ext, 저장소 밖)로 EBOOT 복호화.

### PoC-F1 — 낱개 FAfont14.fon이 세이브 대화를 그리는가
- 기준: 원본 트리, 처음 부팅(세이브 없음) → "セーブデータがありません。…" 대화.
- 조작: `USRDIR/DATA/FAfont14.fon`의 `セ`(글리프 311)를 꽉 찬 사각형으로.
- 결과: 화면 변화 없음 → **기각**. 낱개 파일은 이 소비자의 공급원이 아님.

### PoC-F2 — 네 사본 판별
- 조작: `セ`에 CPK FAfont14 = 꽉 참, CPK cmex = 체크, 낱개 cmex = 가로줄, 낱개 FAfont14 = 세로줄. DAT000은 `tools/cpk.py rebuild`로 재구성(두 폰트 무압축 저장).
- 결과: 첫 줄 `セ`가 꽉 찬 사각형 → **CPK 안 FAfont14.fon 확인**. 재구성 DAT000으로 부팅 정상.
- 증명하지 않은 것: 대사창·메뉴·전투 UI의 글꼴, 글리프 수 증가 허용 여부.

### PoC-K1 — 한글 글리프 + EBOOT 문자열
- 조작: CPK FAfont14에 KS X 1001 한글 2,350자(Galmuri11, 기준선 13행)를 덧붙여 JIS 구 16–40(SJIS 0x889F–0x94FC)에 배정 → 4,494 글리프. 복호화 ELF를 평문 EBOOT.BIN으로 두고 세이브 대화 두 줄을 같은 바이트 길이 안에서 한글로 교체.
- 결과: 한글 정상 표시, 평문 EBOOT 부팅 정상. 다음 대화 "作成しました"의 作成가 한글로 바뀌어 나옴(한자 자리 공유의 직접 증거).
- 관찰: Galmuri11의 1px 세로획이 원본의 굵은 2px 안티앨리어싱 글꼴보다 흐리게 보임(2배 확대 필터 영향 포함) — 글꼴 선택은 사람 결정 사항.

### PoC-K2 — 대사 스크립트 재삽입
- 조작: M001_1.srt의 본문 4개(명령 21, 28, 29, 30)를 길이가 다른 한글 초벌로 교체(`tools/srt.py`, 분기 재배치). 경로: 새 세이브 → 시스템 파일 작성 → 오프닝 START 생략 → NEW GAME → 프롤로그 START 생략 → 첫 대화.
- 결과: 줄바꿈·페이지 넘김·음성 큐 보존, 19자+기호 줄과 16자+기호 줄이 창 안에 표시. 선택지에서 1번(case 0) 선택 → 명령 41 → goto → 명령 62로 정확히 진행.
- 새 사실: `argc`는 문자열 매개변수까지 센다(처음 파서는 문자열 앞 4바이트를 정수로 잘못 읽었음 — 수정하고 회귀 테스트 추가). 노점 주인 이름판이 깨짐 → 화자 이름은 별도 표.
- 증명하지 않은 것: 다른 선택지·default 경로, 창의 최대 폭, 음성 재생 동기(소리 미확인).
- 디버거: 부팅 직후 WebSocket 업그레이드가 수십 초 응답 없음. 한 연결로 여러 입력을 보내는 방식으로 우회.
