## D2 설치 데이터(INS000.DNS) 처리 — 채택 (2026-10-26)

- 질문: 메모리스틱 설치 기능을 어떻게 다룰 것인가.
- 확립된 사실(survey §5 R-INSTALL): 설치본은 `ms0:/PSP/SAVEDATA/ULJS00292HAGINS/INS000.DNS`, 내용은 DAT000.cpk 그대로를 PGD(drm 1, MAC 1, 블록 1024, 키는 EBOOT 0x1a5c50(파일 오프셋)의 16바이트)로 감싼 것. 원본 DAT000에서 INS000.DNS를 **바이트 동일하게 재생성** 성공(오프라인). 설치되어 있으면 게임은 UMD의 DAT000 대신 설치본을 읽음 → 손대지 않으면 설치 사용자에게는 일본어 데이터 + 한글 EBOOT가 섞임.
- 선택지:
  - **A. 설치 지원 유지(권장)**: 패치된 DAT000을 같은 키로 재암호화해 INSDIR/INS000.DNS 교체 + EBOOT의 설치 폴더 이름을 바꿔 기존 일본어 설치본을 무시(재설치 필요). 비용: PGD 암호화를 제품 빌드에 편입(libkirk는 GPLv3 — 자체 구현 또는 라이선스 정리), 설치→로드 런타임 PoC. 위험: 실기의 MAC 검증은 미확인(오프라인 원본 재현은 통과). 패치 크기는 CPK 재구성 시 바뀐 파일을 끝에 덧붙이는 배치로 줄일 수 있음.
  - **B. 설치 기능 끄기**: EBOOT를 고쳐 항상 UMD의 DAT000을 읽고 설치 메뉴를 막음. 비용: 설치 흐름·메뉴 코드 분석(위치 미조사), 남은 진입 경로가 멈춤을 일으킬 위험. 실기에서 로딩이 느려짐. 패치 크기 작음.
  - C. 처리하지 않고 안내만: 설치한 사용자 화면이 깨짐. 비권장.
- 결정: **A. 설치 지원 유지**. 결정자: 프로젝트 소유자(대화).
- 효과: 제품 빌드가 패치된 DAT000으로 INSDIR/INS000.DNS를 생성, EBOOT 설치 폴더 이름 변경, 배포 안내에 재설치 필요 명시. 설치→로드 런타임 PoC가 출시 조건. 실기 미검증이면 지원 주장을 PPSSPP로 한정.
- 재검토 조건: 재암호화 DNS를 게임이 거부, 실기 MAC 실패, 라이선스 문제를 풀 수 없음.

## D3 번역 범위와 방식 — 채택 (2026-10-26)

- 기술 제약: 현재 인코딩은 한글이 JIS 한자 구 16–40을 차지 → 이 영역 한자를 쓰는 번역 안 된 문자열은 엉뚱한 한글로 나옴(PoC-K1/K2에서 관찰). 따라서 **글꼴로 그리는 런타임 텍스트(대사·EBOOT UI·이름 표)는 전부 번역이 사실상 필수**. 일부만 번역하려면 한글을 게임이 쓰지 않는 코드칸에 배치하는 인코딩 재설계가 필요.
- 분량: 대사 341,294자(정확), EBOOT ≤34,510자(상한), mes_j 약 7,000자(추정), 그래픽 글자·동영상 미집계.
- 선택지: (1) 텍스트+그래픽 전부, (2) 텍스트 전부 + 그래픽은 자주 보이는 것(조작 막대·메뉴·타이틀 등) 우선, 나머지 원문 유지, (3) 단계 배포(1차 텍스트, 2차 그래픽), (4) 대사만(인코딩 재설계 필요, 비권장).
- 번역 방식(스킬 규칙): 대량 초벌을 맡기기 전에 대표 표본 번역을 사람이 평가해 범위를 승인. 고유명사·말투 결정 기록 필요. 배포 전 사람 검수.
- 결정: **텍스트 전부(대사·EBOOT UI·이름 표) + 자주 보이는 그림 글자**, 나머지 그림은 원문 유지. 그림 글자 범위는 그림 목록 조사 후 다시 확정. 번역은 **Claude 초벌 + 사람 검수** — 대표 표본과 고유명사·말투 안을 먼저 평가받은 뒤 승인된 범위만 대량 초벌. 결정자: 프로젝트 소유자(대화).
- 재검토 조건: 그림 글자 목록이 나와 범위 확정이 필요할 때, 표본 평가 불합격.

## D4 용어·문체 기준 — 채택 (2026-10-26)

  7. 표본 문장 승인은 **보류** — 실제 표본 검수 후 확정. 검수 기준(인물별): style.md §4.
